# Programming Languages

A programming language is a designed notation for expressing computations and rules. Its syntax and meaning are specified by a language standard, implementation, or both; no single person or organization decides what every language can do. Communities evolve languages through proposals, implementations, and standards.

## Curiosity questions and answers

### 5. Who decides what a programming language can do?

Language designers propose its syntax and semantics. A standards body may formally define a language (as with many versions of JavaScript and C), while implementers build compilers, interpreters, and libraries. Users and maintainers influence its direction through proposals and adoption. A language's specification sets what conforming programs mean, but implementations and available libraries determine what is practical.

### 6. Why are there hundreds of programming languages?

Languages reflect different goals, eras, communities, and trade-offs. One may emphasize fast systems code, another concise data analysis, safe concurrency, browser interaction, or teaching. New languages also experiment with ideas or target a specific platform. Many coexist because no one set of trade-offs is ideal for every problem.

### 7. Why do we need Python, Java, JavaScript, C, C++, Go, Rust, etc.?

They serve different ecosystems and priorities. Python is approachable and has strong scientific libraries; JavaScript runs in browsers and on servers; Java has a mature virtual-machine ecosystem; C and C++ offer low-level control and broad systems support; Go favors simple concurrent network services; Rust aims for low-level performance with strong memory-safety guarantees. These are tendencies, not strict limits—libraries, teams, deployment targets, and existing systems also matter.

### 8. What makes one programming language different from another?

Languages differ in syntax, type systems, memory management, concurrency features, runtime model, performance characteristics, tooling, and ecosystem. For example, one may check types before running, while another checks many operations at runtime. Those design decisions affect how errors are caught, how code is expressed, and what systems it integrates with.
